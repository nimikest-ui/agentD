# Research Report & Implementation Plan: MiMo-Code TUI Clone for agentD

## Research Findings

### MiMo-Code Architecture (verified from source)

**Repo**: `XiaomiMiMo/MiMo-Code` (9.8k stars, MIT license)
**Stack**: TypeScript monorepo, Bun 1.3+, Turbo, SolidJS TUI

The TUI is a **SolidJS app rendered in the terminal** via `@opentui/solid` (a custom terminal UI framework by SST). It connects to a **Hono HTTP/WebSocket server** that handles all LLM interactions, tool execution, and state management.

**Key architectural pattern**: Server-client split
- **Server** (`packages/opencode/src/server/`) — Hono-based API on port 4096, handles agent loop, tool execution, LLM calls, SQLite storage
- **TUI** (`packages/opencode/src/cli/cmd/tui/`) — SolidJS terminal UI, communicates with server via WebSocket
- **Worker** (`tui/worker.ts`) — Runs server in a worker thread when using TUI directly

### What Needs to Be Cloned

For a standalone TUI that works on Linux:

1. **TUI framework layer** — SolidJS + `@opentui/solid` rendering
2. **Chat view** — Message rendering, streaming, markdown
3. **Tool output display** — Bash output, file diffs, search results
4. **Agent switching** — Tab to switch between agents (build/plan/compose)
5. **Input handling** — Text input, keybindings, slash commands
6. **Server communication** — WebSocket client to Python backend

### What Gets Replaced

The **server side** (agent loop, LLM calls, tool execution) stays in Python (agentD's existing `core.py`). We only clone the TypeScript TUI frontend.

### MiMo-Code Style Conventions

- No `try/catch`, use `.catch()`
- No `any` type
- No `else`, use early returns
- No unnecessary destructuring, use dot notation
- `const` over `let`, ternaries over reassignment
- Bun APIs preferred
- Functional array methods over for loops

## Implementation Plan

### Goal

Build a new standalone TypeScript package (`packages/tui/`) in the agentD repo that:
1. Clones MiMo-Code's TUI interface (SolidJS + opentui)
2. Works on Linux
3. Connects to agentD's existing Python backend via HTTP/WebSocket

### Architecture

```
┌─────────────────────────────────┐
│  TypeScript TUI (new package)   │
│  SolidJS + @opentui/solid       │
│  WebSocket client               │
└──────────┬──────────────────────┘
           │ WebSocket/HTTP
┌──────────▼──────────────────────┐
│  Python Bridge (new module)     │
│  FastAPI/Starlette WebSocket    │
│  Wraps agentd.core.Agent        │
└──────────┬──────────────────────┘
           │
┌──────────▼──────────────────────┐
│  agentD Python Core             │
│  agentd/core.py, models.py,     │
│  graph.py, memory.py            │
└─────────────────────────────────┘
```

### Step 1: Set Up TypeScript Package

Create `packages/tui/` with:
- `package.json` — Dependencies: `@opentui/core`, `@opentui/solid`, `solid-js`, `shiki`, `marked`, `diff`
- `tsconfig.json` — Extends root config
- `src/index.ts` — Entrypoint

### Step 2: Build Python WebSocket Bridge

Create `agentd/server.py`:
- FastAPI/Starlette WebSocket server
- Wraps `agentd.core.Agent` for invoke/stream
- Protocol: JSON messages over WebSocket
  - Client → Server: `{type: "message", content: "...", agent: "build"}`
  - Server → Client: `{type: "token", content: "..."}`, `{type: "tool_call", ...}`, `{type: "tool_result", ...}`
- Expose agent state, session management, memory queries

### Step 3: Clone TUI Components

Port from MiMo-Code's `packages/opencode/src/cli/cmd/tui/`:
1. **App shell** — Layout, keyboard handling, route management
2. **Chat view** — Message list with streaming, markdown rendering
3. **Input bar** — Text input, slash commands, agent switching
4. **Tool output** — Bash output, file diffs (using `@pierre/diffs`)
5. **Status bar** — Model info, token count, session status
6. **Sidebar** — Session list, file tree

### Step 4: Wire Up Communication

- WebSocket client in TUI connects to Python bridge
- Stream tokens in real-time
- Display tool calls with expand/collapse
- Show file diffs inline

### Step 5: Linux-Specific

- Ensure `@opentui/solid` works on Linux terminals (xterm, kitty, alacritty)
- Test with common Linux terminal emulators
- Handle PTY for bash tool display

### Verification

1. `bun install` in `packages/tui/`
2. `bun run dev` starts TUI
3. `python -m agentd.server` starts Python bridge
4. TUI connects, sends messages, receives streamed responses
5. Tool calls display correctly (bash output, file edits, diffs)
6. Agent switching works (Tab between build/plan)
7. Works in Linux terminals (tested in xterm/kitty)

### Risk Assessment

- **HIGH**: `@opentui/solid` is a custom framework — may have limited docs/community. Need to study MiMo-Code's usage patterns carefully.
- **MEDIUM**: WebSocket protocol needs to match between TS client and Python server — need clear contract.
- **LOW**: MiMo-Code's tool display is complex — may need to simplify for initial version.
